# GeoGebra 构图

你负责理解题目、选择构法并生成请求；本地工具负责执行、读取事实、核验和交付。用相同的工具组合原语解决新题，不修改源码、不按题型添加分支或套用固定答案模板。

先读取 [能力和请求契约](references/capabilities.md)。从本 Skill 目录向上两级定位插件根目录 `<plugin>`；工具位于 `dist/src/cli.js`。必须使用当前已安装插件的路径，不依赖开发仓库或工作目录。首次安装缺少依赖时，按插件 README 执行 `node <plugin>/scripts/setup-plugin.mjs`；其他故障不要重复安装。运行前执行 `node <plugin>/dist/src/cli.js doctor`，确认返回 ok；失败时先处理依赖和版本问题，不继续构图。不需要额外模型 API Key。

## 生成请求

- 保存用户原文及影响题意的澄清回答。只有缺少影响构造的必要信息时才提问。
- 把每项明确条件映射到带原文来源的 requirement 和可执行检查。保留坐标、名称、数值和呈现要求。自由选择的初始坐标要向用户说明，不能冒充题目给定条件。
- 生成结构化操作和对象引用。使用命令组合构造真实依赖。显示对象、连线和圆等要求还应检查对象类型，不能只检查几个点的数值关系。
- 随自由点变化应保持的关系用 `sampled`，并选择相关自由点及非退化拖动样本；明确的初始坐标用 `initial`。派生关系应包含依赖检查，不能用固定坐标冒充动态构造。
- 对每项关键呈现要求添加 style 检查。复杂布局、无限区间和通用证明不在当前核验范围内。无法核验的必需要求必须说明，不能删去条件后宣称成功。
- 调用前逐项对照题干自审，检查条件覆盖、命令能力、对象引用和样本是否相关。工具不能自动证明自然语言提取完整。

## 执行和反馈

将请求保存为 JSON 文件，使用绝对路径：

```sh
node <plugin>/dist/src/cli.js build --request <absolute-request.json>
```

构图、重载、拖动及 Playwright 验证均使用 headless，不在中间步骤打开可见浏览器。工具将成功截图保存为交付目录中的 preview.png；需要诊断截图时也保存到工作区。

读取返回的 JSON 和失败运行中的 `verification.json`、`run.json`。修正程序时保留原始要求，不放宽容差，不提交模型自判的 `passed`。最多尝试三次，每次工具从空白 applet 开始；仍失败时报告具体要求、能力缺口或错误，不在半完成画布上追加操作。

成功结果若带 warnings，向用户说明诊断写入问题；完整交付目录仍有效，不因此重新作图。失败时从 error.details.run 定位诊断，保存失败信息；不连接残留画布。

全部验证成功后，再用本机 Google Chrome 打开交付目录中 result.ggb 的交互预览：

```sh
node <plugin>/dist/src/cli.js preview --delivery <absolute-delivery-dir>
```

预览需要本机已安装 Google Chrome；不要直接导航到 .ggb 文件，用上述命令加载文件。预览是前台进程，使用宿主的进程会话保持运行。等待就绪 JSON；仅打开窗口不算完成。交付 `result.ggb`、检查报告和截图，说明已验证的条件及有限交互样本。采样通过不等于一般命题已证明。预览失败时保留文件并单独报告展示错误。
