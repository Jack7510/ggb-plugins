# GeoGebra 二维数学与代数

你负责理解题目、选择构法、生成原生数学程序和独立检查；工具负责真实执行、事实采集、核验和交付。新题改变程序，不增加题型分支、命令包装或专用旁路脚本。

## 分析与作图边界

- 只分析已知条件、对象关系和构图方法，交付用于观察与探索的图形。不提供选项判断、待求数值、最终关系结论或完整解题证明，也不从示例答案中复制这些内容。
- 此规则覆盖过程回复、最终回复和可见产物。caption、Text、截图及可见代数对象不得直接揭示待求答案；可保留题目已给定的信息、对象名称和必要的构图说明。
- 构图和独立核验仍可使用必要计算、CAS 和 expected 值。保留完整请求、核验报告和失败证据，不删必需条件、不放宽容差；审计数据中的内部计算不作为解答主动展示。
- 原题要求求解时，保留原文并说明本插件只提供分析与作图。区分原题待求目标和本次构图验收，不把图形核验通过说成原题已解答。无法在此边界内构图时说明限制，不静默删除条件。

先读取 [能力和请求契约](references/capabilities.md)。从本 Skill 目录向上两级定位 `<plugin>`。只调用当前安装副本的 `dist/src/cli.js`，不依赖开发仓库。首次缺少依赖时按插件 README 执行 setup-plugin；其他故障不要重复安装。在本宿主会话首次使用该安装副本时调用 `node <plugin>/dist/src/cli.js doctor`，确认 smoke、casSmoke 通过。同一会话、同一安装副本未变化时复用这次结果；新会话、插件升级、runtime 重装或环境错误后必须重新执行。不读取其他会话的成功标记来跳过检查。build 和 preview 始终执行各自的运行时及数学门禁；不需要额外模型 API Key。

## 工作语言

支持中文和英文，locale 取题目语言：中文题目用 zh-CN，英文题目用 en；caption、Text 与预览提示同语言，无需为语言单独询问。回复、澄清问题、讲解、caption 和 Text 对象使用所选语言；用户明确指定的名称或文字优先。请求 locale 设为 zh-CN 或 en，最终预览界面跟随该选择。题目原文、source、已发生的澄清及 assumptions 保留来源语言，不为翻译改变条件。GeoGebra 命令、协议字段、错误码保持固定名称；Agent 用所选语言解释原始诊断。中文 Skill 文档不限制实际工作语言，不创建两份 Skill。

## 生成程序与检查

- 保存原文、来源和实际澄清。图片先转述题干及图中的明确条件，不能把图形比例当作已知数值。仅在必要条件有歧义时提问。
- 按协议 2 生成 native 步骤。GeoGebra 原生引擎处理命令、函数、表达式及重载；必要时查询官方手册。不用旧八命令表限制新题，不写 Python/JavaScript 构图旁路。
- 优先使用包内已确认的接口和用法，只在语法或重载不确定时查询官方手册。核验与截图已满足要求后结束构造，不追加无关美化或重复核验。
- 每项题目条件关联 requirement 的原文 source 和检查。自行选择的初始坐标必须说明。显示、标签、颜色、线宽等要求也要检查，关键对象声明可见。题干点名的图形必须真的画出来（三角形要有 Polygon 或三条边，圆要有 Circle），并用 type／exists／周长或半径检查覆盖；只放顶点不算画出图形。
- source 使用原题的准确片段，保留自行选择初态与题目条件的区别。声明全部实际输出；id 与显式 outputs 共用保留字和内置名称保护，原生语法及实际输出仍由固定引擎核验。静态 check 不保证语义。需要细节时读取能力契约，不用反复试错补写命令规则。
- 用真实命令依赖构造联动。路径点可用 initial 初始化；CAS 步骤是当次结果物化，不自动成为动态 CAS 构造。对动态要求另加依赖和相关交互检查。具有可操控输入的 sampled 数学关系必须由相关输入变化覆盖；固定量仍在每个样本复验，不能把无关移动当作联动证据。
- 依赖来自隔离引擎副本的真实对象关系；证据不足时保留失败，不用名称匹配或同时变化冒充依赖。参数改变对象数量时，工具会在同一副本恢复原值；优先选择规模受控、往返后全部对象仍有定义的原生表示，不要求工具忽略隐藏的未定义对象。
- 拖动初态避开与其它可见点同址，包括可移动点和 `fixed:true` 的固定点。工具报告歧义目标时，按证据调整自行选择的初态或相关样本；不能把鼠标拖动改成坐标赋值后宣称通过。
- 数学关系用原生 expression 检查：布尔期望 true/false，数值或 CAS 恒等差期望具体数值；列表／矩阵用嵌套 expected。检查需要明确实际结果类型和单位；语法及单位换算示例见能力契约。CAS 假设必须来自用户原文或明确的澄清回答，并在 assumptions 中显式声明；Agent 提问不授予假设，用户否定的条件不能采用。检查必须引用相关实际对象，不能用常量、自我复述或只看截图代替条件核验。
- 期望值先算后写：坐标、距离、面积、角度等 `expected` 要按题目条件和本次构造独立算出再写进请求，不从 `build` 的失败证据或上一轮观测里抄数值——抄观测会让检查变成自复述。观测与推导不一致时，先按证据判断是构造错了还是算错了，再落笔。
- 区分构造正确性、题设约束和交互行为，分别用 requirement 的 purpose 标为 construction、constraint、interaction。该字段只记录证据目的，不改变核验门禁。warnings 说明执行证据的边界，不按命令名认证或否定独立性；构造关系检查应保留，需要独立证据时从原题另行推导，不添加无关等式。
- 明确初始范围、定义域、条件解和有限样本。纯代数使用 display:algebra，可无自由点及交互；几何按需声明真实拖动样本，滑块用 parameter/value 采样；报告区分原生参数设置和鼠标拖动。超出实际核验范围的必需要求不能删除后宣称通过。
- 题目只说「正多边形」而未给边数时，边数是构图参数而不是固定值：用滑块（`n=Slider(3,10,1)`）加 `poly=Polygon(Sequence(Rotate(A, 2*pi*k/n, O), k, 0, n-1))` 表达，只声明 `poly`，让用户拖动边数。用户明确给出边数时才固定（如正五边形）。固定顶点形式会生成自动边名，仅在题目给定边数且需要逐点核验时使用。核验用与边数无关的聚合不变量：面积、周长、顶点半径最大偏差、边长最大偏差，并在采样的 n 下复验；不把自选或滑块的当前值说成题目条件。
- 动态是默认：题目中的可变量——边数、半径、角度、动点位置——表达成滑块或可拖点，不固化成常数；核验必须覆盖「变」，在采样的参数值下复验聚合不变量与依赖关系，只验初始状态不构成动态证据。给定具体数值或用户要求静态图时才固定，并说明取舍。

## 编辑已有 GGB

用户提供已有 GGB 并要求改颜色、线型、填充、可见性或标签时，走编辑模式，不重画、不重建。

- 先运行 `inspect --ggb <绝对路径>`。按返回的对象清单（名称、类型、当前颜色/线型/填充/可见性、定义、是否依赖）对齐用户说法；指代不明或多解时先问，不猜对象。请求里的 `base.sha256` 用 inspect 返回的值；文件改动后重新 inspect。
- 只声明用户要求的字段，`edits` 每个对象一次。把每项都写成 requirement 的 `style` 检查，`source` 用本次指令原文。编辑请求不写 `program`、`styles`、`view`、`interactions`。
- 工具保证“除声明字段外逐字段不变”。因此不要顺手改别的对象、不要调整视图或重排对象；改多了会被 `preservation_violation` 拒绝，这正是要保留的证据。
- `filling` 只对封闭图形有效；线型/线宽只对有轮廓的对象。依赖对象可以改样式，但值由几何关系决定，改不了也不该改。
- `edits` 只支持显示属性。用户要求增加对象、改坐标或数值时，改用下面的继续构造；要求删除、重命名、拖动样本或改视图时，说明不支持，不把旧图形翻译成程序重画。
- inspect 或 build 报 `base_unsupported`（脚本、自定义工具、图片、按钮、输入框、三维材料）时，说明该文件超出支持范围，请用户提供二维、无脚本的文件；不尝试绕过。
- 交付多出 `base.ggb` 和 `diff.json`。答复时逐项说明实际变化（对象、字段、前后值），并说明未改动其它对象；`diff.json` 与报告不一致时以工具结论为准。
- 编辑失败同样最多三次新运行；不删声明字段、不放宽容差、不改用坐标赋值来规避。

### 继续构造

用户要求在已有图上增加对象、移动独立点或修改独立数值时，保留同一 `base`，改发构造修改。不要与 `edits` 混用。

- `plan.program` 只写新增的 native 步骤；参数可引用基线标签，新输出不得与基线重名，并声明引擎实际返回的全部标签。
- `plan.updates` 每个对象一条：数值对象用 `value`，可移动点用 `coords`。目标必须 `independent`；滑块值在 `slider` 区间内；不更新依赖对象。
- `plan.styles` 可同时设置基线和新对象；基线对象不要 `fixed`，显示字段与编辑模式相同。
- 检查覆盖每个新增对象、更新和样式。依赖对象会因更新重算，不要声明它们不变，也不要为它们补未要求的检查。
- 不写 `view`、`edits`、`interactions`。工具按差异白名单拒绝删除、重命名、未声明新增、未声明字段变化和依赖对象变为未定义。
- inspect 摘要中的 `x`、`y`、`value`、`slider` 是当前状态；更新前先读取，不用旧提示词中的值猜测。

## 执行与交付

保存 JSON，使用绝对路径；`outputDir` 填用户工作目录根，并用 `title` 概括题目（不超过 60 字）：

```sh
node <plugin>/dist/src/cli.js check --request <absolute-request.json>
node <plugin>/dist/src/cli.js build --request <absolute-request.json>
```

交付落在 `<outputDir>/<title>/delivery/<title>.ggb`：目录和文件名都取 `title`，缺少 `title` 时由 `prompt` 派生。同名交付已存在时自动加 `-2`、`-3`，不覆盖旧文件；把实际路径报告给用户，不要让用户自己找 `output/ggb-XXXXXX`。

check 只做结构、来源和声明引用检查，不启动浏览器，不写交付，也不证明 GeoGebra 语法或数学关系成立。修正预检错误后再 build；两种命令的失败与修复均保留记录。

构造、重载、探针和交互验证均 headless，不打开中间窗口。截图保存为交付目录的 preview.png；失败诊断写在工作区。

读取返回 JSON、verification.json 和 run.json。按证据修正程序，保留原始要求，不放宽容差、不提交自判 passed。最多三次，每次是新运行和空白 applet；仍失败就说明具体条件及能力缺口，不在残留画布续接。
每次失败只改证据指出的那一项：`verification_failed` 的 details 给出被检查对象的事实，用它定位是构造还是期望值出错；不改与失败无关的步骤和检查，不顺手重排程序。

成功若带 warnings，说明诊断写入问题，完整交付仍有效。全部验证成功后，必须把自动打开生成文件作为最后的工具动作，无需等待用户再次要求。调用：

```sh
node <plugin>/dist/src/cli.js preview --delivery <absolute-delivery-dir>
```

preview 使用系统默认浏览器，在本地 GeoGebra 页面加载同一交付 GGB；不直接打开可能被下载的 .ggb URL。保留前台进程，等待浏览器页面确认加载的就绪 JSON，再答复用户。页面“结束预览”按钮或进程取消会释放本地服务；仅关闭默认浏览器标签页不保证结束进程。自动化复核使用 --headless --once，复核后自动释放资源并退出；不能代替最终可见预览。预览失败保留文件并单独报告，不能声称已经打开。

交付 GGB、报告和截图，说明已验证条件及有限样本。覆盖记录见 [固定 runtime 覆盖边界](references/command-coverage.md)。不宣称全部原生命令已验收，不把数值采样或未决 CAS 结果当作一般证明。旧协议 1 的请求与交付须按新契约重新生成。
